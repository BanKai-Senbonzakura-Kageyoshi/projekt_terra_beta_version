# Каталог ресторанов Terra

Небольшой каталог ресторанов Душанбе: Django, SQLite, HTML-шаблоны, Tailwind CSS и немного JavaScript. Код намеренно оставлен простым. Карта использует Leaflet и OpenStreetMap через CDN, без ключа API.

## Запуск на компьютере

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
```

В Linux или macOS:

```bash
source .venv/bin/activate
```

В Windows:

```powershell
.venv\Scripts\activate
```

Установите Django и создайте таблицы базы:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Чтобы добавить тринадцать заведений Душанбе из OpenStreetMap:

```bash
python manage.py load_dushanbe_restaurants
```

Команда безопасна для повторного запуска и добавляет тринадцать заведений. Названия и координаты взяты из открытых данных OpenStreetMap. Там, где карта не содержит точного адреса, показан только город. Данные могут быть неполными или устареть — проверьте их перед публикацией. Использование данных OpenStreetMap регулируется лицензией ODbL; источник и атрибуция показаны возле карты.

Чтобы создать черновые примерные меню из 26 блюд в 13 категориях для ресторанов Душанбе:

```bash
python manage.py add_sample_menus
```

Это только идеи блюд, ориентировочные цены и иллюстративные фотографии — не реальные опубликованные меню. На странице каждого такого ресторана посетители увидят заметное предупреждение.

Чтобы добавить фотографии блюдам, у которых их ещё нет:

```bash
python manage.py add_menu_photos
```

Команда безопасна для повторного запуска и добавляет иллюстративные стоковые фотографии. Эти изображения не подтверждены ресторанами и могут отличаться от реальной подачи. При добавлении нового блюда владелец указывает ссылку на его фотографию.

Откройте главную на `http://127.0.0.1:8000/`, каталог — на `http://127.0.0.1:8000/restaurants/`, меню — на `http://127.0.0.1:8000/menu/`, кабинет владельца — на `http://127.0.0.1:8000/owner/`, модерацию — на `http://127.0.0.1:8000/moderation/`, столики — на `http://127.0.0.1:8000/owner/tables/`, а служебную админку Django — на `http://127.0.0.1:8000/admin/`.

## Как устроен проект

- `terra_site/settings.py` — основные настройки Django и подключение SQLite.
- `restaurant/models.py` — рестораны, категории и блюда меню, фотографии, контакты, заявки.
- `restaurant/admin.py` — простая панель для редактирования содержимого и просмотра заявок.
- `restaurant/forms.py` — проверки данных, которые посетитель отправляет с сайта.
- `restaurant/views.py` — CBV и простые функции: каталог, карточки ресторанов, вход владельца, меню, бронирования и общий контекст.
- `restaurant/urls.py` — адреса страниц сайта.
- `restaurant/templates/restaurant/` — HTML-шаблоны. Каждая страница имеет собственные `<!doctype html>`, `<html>`, `<head>` и `<body>`. Общие шапка, подвал и окно бронирования подключаются небольшими шаблонами-фрагментами.
- `restaurant/static/restaurant/css/site.css` — собственные стили и мобильная версия.
- `restaurant/static/restaurant/js/site.js` — мобильное меню, окно бронирования, галерея и мягкое появление блоков.

## Логика в нескольких шагах

1. Посетитель открывает адрес сайта.
2. Django находит адрес в `restaurant/urls.py`.
3. CBV из `restaurant/views.py` получает данные из модели (если они нужны) и передаёт их HTML-шаблону. Общая функция добавляет шаблону язык, настройки сайта и форму бронирования.
4. Форма проверяет имя, телефон, дату, количество гостей и согласие на обработку данных.
5. Если всё правильно, Django сохраняет заявку в SQLite. Онлайн-заявки доступны только для одобренных заведений, у которых назначен superuser-владелец. Этот владелец рассматривает их в `/owner/bookings/`.
6. Владелец выбирает свободный столик подходящей вместимости и подтверждает бронь либо отклоняет заявку. Столик остаётся занятым до тех пор, пока владелец не отметит, что гости ушли.

Это и есть MVT: **Model** хранит данные, **View** готовит страницу или обрабатывает форму, **Template** показывает HTML.

В `views.py` общий класс `SiteContextMixin` используется всеми страницами. Он запоминает язык в сессии и добавляет общий контекст. Для учебного проекта так проще найти эту логику в одном файле.

## Заполнение сайта

Владельцам выдаются доверенные аккаунты суперпользователей. Первый аккаунт создаётся командой `python manage.py createsuperuser`; дополнительные — существующим администратором в `/admin/auth/user/add/` с включённым флагом «Статус суперпользователя». Публичная регистрация создаёт только обычный аккаунт и не выдаёт права управления.

В кабинете `/owner/` владелец добавляет ресторан; новая заявка появится в `/moderation/`. Суперпользователь проверяет фотографию и сведения и одобряет публикацию либо отклоняет её с причиной. Владелец управляет столами в `/owner/tables/`, а заявками — в `/owner/bookings/`. Подтверждённая бронь делает столик недоступным для других заявок на ту же дату, пока владелец не нажмёт «Гости ушли · освободить столик».

Владелец отмечает адрес ресторана кликом по карте и загружает фотографию файлом. Для добавления блюда он также загружает фотографию с устройства; вставлять URL изображения не требуется. Загруженные файлы сохраняются в `media/`. Для production-сервера настройте отдельное обслуживание пользовательских медиафайлов.

Администратор сайта может также добавлять:

1. рестораны и доверенные аккаунты владельцев;
2. категории и блюда с названиями, составом и ценой;
3. фотографии галереи — указывайте оптимизированную ссылку и описание изображения;
4. настройки сайта.

Если часы ресторана или телефон ещё не подтверждены, оставьте их пустыми. Сайт не подставляет придуманные контакты и часы.

## Что намеренно упрощено

- Tailwind подключён с CDN, поэтому при разработке не нужно устанавливать Node.js. Для CDN нужен интернет; для производственного запуска лучше собрать Tailwind локально.
- Команда `load_dushanbe_restaurants` добавляет 13 названий и координат из OpenStreetMap. Добавляйте блюда и категории через кабинет владельца или Django Admin, используя опубликованное меню конкретного ресторана.
- Кнопка определения местоположения спрашивает разрешение браузера и показывает точку только после нажатия. Она не сохраняет координаты посетителя.
- Заявки сохраняются в SQLite. Владелец видит только заявки своих ресторанов; подтверждение требует назначения доступного столика нужной вместимости. Уведомления в Telegram и аналитика не подключены.
- Новые рестораны владельца скрыты до одобрения администратора. Владелец может добавлять категории и блюда только в свои рестораны.
- Политика конфиденциальности содержит заметный примерный текст. Перед публикацией замените его на утверждённый текст.
- Русская и английская версии имеют переключатель; содержание меню редактируется на двух языках в панели администратора.
